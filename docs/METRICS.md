# 수익 계산과 추천 기준

차량을 바꿨을 때 **기사가 얼마를 더 벌고, 회사 매출이 얼마나 오르는지** 를 계산하는 규칙입니다.
이 문서의 값이 Gold 3종과 대시보드 숫자를 전부 결정합니다.

## 1. 순수익 계산

```
기사 월 순수익  = 한 달 수령액(driver_pay + tips)
                 − 한 달 연료비(주행거리 × 마일당 연료비)
                 − 월 렌트료

마일당 연료비   = 내연/하이브리드 : 휘발유 $/gal ÷ combined_mpg
                  EV             : (kwh_100mi ÷ 100) × 전기 $/kWh
```

기사의 순수익은 *운행 패턴 × 차량 연비 × 그달 연료 단가 × 렌트료* 의 함수라 감으로 계산할 수 있는 값이 아닙니다.
`tolls` 는 순수익에서 빼지 않습니다 — HVFHV 의 `tolls` 는 승객 요금 항목이라 기사 부담이 아닙니다.

## 2. 교체 시뮬레이션

```
기사 예상 이득  = 추천 차량 예상 순수익 − 현재 순수익
회사 매출 이득  = 추천 차량 월 렌트료 − 현재 차량 월 렌트료
```

**기존 운행 기록을 그대로 두고 차량만 바꿔** 계산합니다.
"차를 바꾸면 더 많이/적게 뛸 것" 같은 행동 변화는 가정하지 않습니다 — 근거가 없고, 넣는 순간 추천이 검증 불가능해집니다.

| 항목 | 계산 |
| --- | --- |
| **매출** | 등급이 오르는 차(Uber Comfort / Lyft Extra Comfort 자격)로 바꾸면 OD 별 요금 배수를 운행 기록에 곱함 → [3장](#3-요금-배수는-어디서-오는가) |
| **연료비** | 바뀐 차량의 연비·연료 종류로 다시 계산 |
| **렌트료** | 카탈로그의 주간 렌트료를 그달 계약 일수로 환산 |

## 3. 요금 배수는 어디서 오는가

원천 API가 매칭 전에 확정한 `estimated_service_tier`를 제공합니다.
Silver는 등급을 다시 추정하지 않고 license–등급 조합을 검증한 뒤 그대로 전달합니다.
등급 배수는 상수로 가정하지 않고 **우리 운행 데이터에서 직접 계산**합니다.

```
① Silver — 원천 등급 전달 (`monthly_taxi_trip_bronze_to_silver`)
   HV0003 → Standard / Comfort
   HV0005 → Standard / Extra Comfort

② Gold — license·등급별 배수 산출
   마일당 요금 = driver_pay 합계 ÷ trip_miles 합계
   (license, 등급) 별 마일당 요금 → 피벗
     comfort_multiplier       = Comfort 마일당 요금       ÷ Standard 마일당 요금
     extra_comfort_multiplier = Extra Comfort 마일당 요금 ÷ Standard 마일당 요금
```

| 판단 | 근거 |
| --- | --- |
| **원천 등급을 Silver에서 재추정하지 않음** | 실제 상품 등급을 운임 추정치로 덮어쓰지 않음 |
| **마일당 요금은 합계/합계로 계산** | 짧은 운행의 극단값이 단순 평균을 왜곡하지 않음 |
| **관측치가 없는 등급은 배수 1.0** (= 가정하지 않음) | 데이터가 없는 등급에서 매출 증가를 지어내지 않음 |
| **이미 프리미엄 요금으로 뛴 운행에는 곱하지 않음** | 중복 가산 방지 |

---

## 4. 추천 계산 책임

Silver→Gold는 추천 대상을 고르거나 기준선을 적용하지 않습니다. 기사×후보 차량의
수익 시뮬레이션과 같은 월의 리스 차량 재고를 각각 Gold에 적재합니다.

추천 기준과 최종 선택은 이 파이프라인의 소비 계층이 두 테이블을 사용해 결정합니다.
따라서 Gold에는 추천 기준선이나 추천 기사 수 같은 파생 요약을 저장하지 않습니다.
