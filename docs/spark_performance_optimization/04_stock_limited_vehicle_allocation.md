# Spark DataFrame으로 재고 한도 안에서 차량 배정하기

- 요약
  - 기사마다 가장 좋은 차량을 독립적으로 고르면 같은 모델의 실제 재고를 초과할 수 있음
  - 기사×차량 후보를 만든 뒤 기사별 선호 순위와 모델별 경쟁 순위를 Window 함수로 계산
  - 순위 라운드마다 기존 점유량과 앞선 배정량을 빼고 남은 수량만큼만 배정
  - 여러 순수익 임계값을 하나의 그룹 컬럼으로 만들어 라운드 루프 한 번에서 서로 독립된 결과를 계산

## 문제

차량 추천은 기사별 점수 정렬만으로 끝나지 않는다. 여러 기사가 같은 차량 모델을 1순위로 선택할 수 있지만 실제 차량 수는 제한돼 있다.

기사별로 Python 반복문을 돌며 재고를 하나씩 줄이면 데이터가 드라이버 프로세스로 모인다. 기사 수가 늘수록 단일 프로세스가 병목이 되고 Spark의 분산 계산을 사용하기 어렵다.

회사는 기사 순수익을 우선하는 정책과 회사 매출을 우선하는 정책을 함께 비교한다. 두 번째 정책은 순수익 증가 하한을 100, 200, 300, 400, 500으로 바꿔 결과를 비교한다. 임계값마다 전체 재고 배정 루프를 따로 실행하면 같은 후보 계산과 같은 라운드 처리가 다섯 번 반복된다.

## 접근

배정 문제를 두 개의 순위로 나눴다.

1. 각 기사가 어떤 차량을 먼저 원하는지 정한다.
2. 같은 차량에 여러 기사가 몰리면 누구에게 먼저 줄지 정한다.

기사별 순위는 `Window.partitionBy(driver_id)`로 계산한다. 모델별 경쟁 순위는 `Window.partitionBy(vehicle_model_id)`로 계산한다. 임계값 비교에서는 두 Window에 임계값 컬럼을 함께 넣어 각 임계값을 독립된 시나리오로 취급한다.

## 해결

먼저 기사 N명과 차량 모델 M개의 후보 N×M개를 만든다. 각 후보에는 예상 연료비, 월 임대료, 기사 순수익, 기사 순수익 증가액, 회사 매출 증가액을 붙인다. 현재 차량인지도 함께 표시한다.

후보 수가 정확한지 배정 전에 검사한다. 기대 행 수는 `기사 수 × 차량 모델 수`다. 실제 행 수, 고유한 기사·차량 조합 수, 후보에 남아 있는 기사 수를 한 번의 집계로 확인한다.

각 기사는 자신의 후보를 정책 순서로 정렬한다. 라운드 1에서는 모든 기사의 1순위 후보를 모은다. 같은 모델에 여러 기사가 몰리면 모델별 경쟁 순위를 매긴다. 다음 수식만큼만 통과시킨다.

```text
이번 라운드에서 배정할 수 있는 수
= 전체 재고 - 기존 보유자의 점유량 - 앞선 라운드의 신규 배정량
```

배정되지 않은 기사만 다음 순위 라운드로 넘어간다. 현재 차량 유지는 재고 경쟁에서 별도로 남겨, 더 나은 교체 후보를 얻지 못한 기사도 결과에서 빠지지 않게 한다.

기사 순수익 우선 정책은 순수익이 큰 후보를 먼저 보고, 회사 매출이 증가하는 교체만 허용한다. 회사 매출 우선 정책은 매출 증가가 큰 후보를 먼저 보되 기사 순수익 증가액이 설정한 임계값 이상이어야 한다.

여러 임계값은 후보에 `threshold` 컬럼으로 붙인다. 랭킹, 사용 재고, 모델별 경쟁을 임계값별로 나누므로 각 시나리오는 서로 재고를 공유하지 않는다. 회사 매출 우선 정책은 임계값마다 라운드를 따로 돌지 않고 모든 임계값이 하나의 라운드 반복을 공유한다. 기사 순수익 우선 정책은 별도로 한 번 실행하며, 두 정책의 결과는 같은 Spark 작업에서 합친다.

## 검증

재고 배정 테스트에서 다음 상황을 확인했다.

- 현재 차량을 이미 쓰는 기사 수를 재고에서 먼저 차감한다.
- 재고가 0인 교체 후보는 선택하지 않는다.
- 같은 모델을 원하는 기사가 많아도 모델별 배정 수가 재고를 넘지 않는다.
- 한 정책 또는 한 임계값에서만 기사가 빠져도 검증이 실패한다.
- 임계값별로 기사 한 명당 결과가 정확히 한 행인지 확인한다.

회사 매출 우선 정책 테스트에는 결과를 손으로 확인할 수 있는 작은 예제를 사용했다.

| 후보 | 기사 순수익 증가 | 회사 매출 증가 | 결과 |
|---|---:|---:|---|
| D | 70 | 20 | 임계값 60에서 선택 |
| E | 30 | 60 | 임계값 20에서 선택 |
| G | -110 | 200 | 모든 임계값에서 제외 |

임계값 20에서는 E, 임계값 60에서는 D가 선택되는지 확인했다. 임계값이 100이면 조건을 넘는 교체 후보가 없어 현재 차량을 유지하는지도 확인했다.

여러 임계값으로 복제된 현재 차량 행을 실제 점유 차량 수로 잘못 세는 회귀 테스트도 추가했다. 임계값이 세 개여도 기존 보유자 한 명은 재고 한 대만 점유하는 것으로 계산됐다.

## 결론

기사별 추천과 모델별 재고 경쟁을 두 Window 순위로 표현했다. Python으로 전체 기사를 모으지 않고 Spark DataFrame 안에서 재고를 차감하며 배정한다.

라운드 수는 기사별 후보 수의 최댓값까지 늘어난다. 차량 모델 수가 크게 증가하면 라운드 수와 N×M 후보 행 수도 함께 증가한다. 이 경우 후보를 만들기 전에 업무상 불가능한 모델을 줄일 수 있는지 먼저 검토해야 한다.
