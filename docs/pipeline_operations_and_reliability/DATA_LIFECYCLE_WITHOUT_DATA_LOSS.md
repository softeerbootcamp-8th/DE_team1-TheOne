# 최신 정상본은 보호하고 오래된 버전만 정리

## 요약

- 지역·월별 최신 정상본은 기간과 관계없이 보호하고 90일 지난 구버전만 정리한다.
- 삭제 전 dry-run을 지원하며, S3와 PostgreSQL의 일부 삭제 실패를 성공으로 처리하지 않는다.

## 문제

데이터를 버전별로 보존하면 S3와 PostgreSQL 사용량이 계속 늘어난다. 하지만 날짜만 보고
삭제하면 90일 넘게 갱신되지 않은 지역·월의 최신 정상본과 복구 기준까지 잃을 수 있다.

정상 완료본, 품질 검증에 실패한 격리본, 작업 도중 남은 불완전한 버전도 구분해야 한다.
상태를 보지 않고 지우면 대시보드 데이터뿐 아니라 장애 조사 근거도 사라진다.

## 보존 정책

| 버전 상태 | 처리 |
| --- | --- |
| 지역·월별 최신 정상본 | 기간과 관계없이 보호 |
| 90일 이내 버전 | 보존 |
| 90일 지난 구버전·격리 버전 | 삭제 |
| 상태 충돌·경로 오류·버전 이력 누락 | 삭제하지 않고 실패 |

삭제 후보를 고르기 전에 지역·월별 최신 정상본을 먼저 찾는다. 최신 정상본은 생성 시각과
관계없이 보호하고, 나머지 버전에만 보존 기간을 적용한다.

정리 DAG는 매일 03시에 한 번만 실행한다. S3 객체는 최대 1,000개씩 삭제하며 일부라도
실패하면 작업을 실패시킨다. PostgreSQL의 결과와 버전 이력은 한 트랜잭션으로 삭제한다.

실제 삭제 전에는 dry-run으로 후보, 객체 수, 보존·삭제 이유를 확인할 수 있다.
경로를 해석할 수 없거나 완료와 격리 표시가 충돌하면 추측해서 삭제하지 않는다.

## 검증

| 상황 | 결과 |
| --- | --- |
| 최신 정상본이 90일을 넘김 | 보호 |
| 오래된 구버전 | 삭제 |
| 최근 격리 버전 | 보존 |
| dry-run | 기록만 남김 |
| S3 일부 삭제 실패 | 작업 실패 |
| DB 일부 삭제 실패 | 전체 rollback |
| 재실행 | 이미 삭제된 항목은 생략 |
