# 8월 24일 의사 결정 목록

---

1. 지역별 Airflow DagRun 동시 실행 상한
   - 결정: 지역 파티션을 받는 `main/` DAG 8개의 `max_active_runs`를 3으로 둔다.
   - 결정: 상한은 `MAX_ACTIVE_SERVICE_AREA_RUNS` 한 곳에서 관리하고 계약 테스트로 고정한다.
   - 결정: LocalExecutor의 `parallelism=32`는 유지한다. EMR와 하위 DAG 대기는
     `deferrable=True`라 기다리는 동안 worker slot을 반환한다.
   - 범위: 이 값은 세 지역 DagRun의 동시 실행을 허용할 뿐 지역별 DagRun을 자동 생성하지 않는다.
   - 기각: worker slot 선제 증설은 단일 EC2의 scheduler와 CPU·메모리 경쟁을 키우며,
     현재 세 지역 규모에서 queued 병목을 입증한 측정값이 없다.
   - 기각: Celery/Kubernetes Executor 전환은 세 지역 규모에 비해 운영 복잡도가 크다.

2. Gold 세 번째 물리 테이블을 `monthly_report`에서 `lease_vehicle_inventory`로 교체한다 (#915)
   - 결정: Silver→Gold 계산은 재고를 참조하지 않고 기사×후보 차량 수익 팩트만 만든다.
   - 결정: 입력 Silver `lease_vehicle_inventory`의 업무 컬럼을 그대로 Gold에 적재하고 Gold 버전·지역·월 키만 추가한다.
   - 변경: 8월 23일 5번의 `monthly_report` 물리 적재 결정을 대체한다.
   - 기각: 두 테이블을 함께 적재하면 소비 계층에서 다시 계산할 요약을 중복 보관하게 된다.
   - 기각: 시뮬레이션에 재고를 반영하면 평가 팩트와 추천 실행 정책이 다시 결합된다.

3. Bronze·Silver S3 공개 방식 (#912)
   - 결정: writer는 최종 경로에 직접 쓰고, Airflow 검증 성공 후 `_SUCCESS`를 기록한다.
   - 결정: 재쓰기 전에 기존 marker를 제거하며 downstream은 marker 없는 파티션을 읽지 않는다.
   - 결정: Spark가 쓰기 종료 때 자동 생성하는 `_SUCCESS`는 비활성화한다.
   - 적용: 원천 API 3종과 EIA의 Bronze 5종·Silver 6종에 같은 계약을 사용한다.
   - 기각: `.staging`에서 최종 경로로 copy+delete하는 방식은 S3 데이터 이동 비용이 중복된다.
   - 기각: 별도 manifest·lock 계층은 지역별 `max_active_runs=3`인 현재 동시성에 과하다.
   - 변경: EIA Bronze는 `year_month/collected_at=<UTC>/<원본명>`, CLEAN Silver는 `year_month/source_collected_at=<UTC>/<기존명>`에 쓴다.
   - 변경: 통합 연료비 Silver는 `year_month/input_version=gas-<token>__ev-<token>/ny_fuel.parquet`에 써 동일 입력 재처리는 덮어쓰고 다른 입력 조합은 보존한다.
   - 기각: 통합 결과에 실행 `collected_at`을 쓰면 같은 입력 재처리도 매번 새 버전으로 오인된다.
   - 배포: 기존 파일은 삭제하지 않는다. 필요한 과거 파티션은 상류 DAG를 재실행해 검증·marker를 생성한 뒤 downstream을 실행한다.

4. Gold 차량 추천과 재고 배정을 Spark 책임으로 복구한다 (#927)
   - 결정: 실제 기사 N명×재고 모델 M개 후보의 거리대별 등급 수입·연료비·리스료·예상 순수익을 Spark에서 계산한다.
   - 결정: 현재 차량 점유분과 앞선 배정 수를 재고에서 차감하고, 재고가 소진된 후보는 다음 순위로 넘겨 기사당 1대를 배정한다.
   - 결정: Gold는 `driver_aggregation`, `driver_car_suggestion` 두 물리 테이블만 같은 버전으로 적재한다.
   - 변경: 2번의 재고 미반영·재고 테이블 적재 결정과 8월 23일 5번의 소비 계층 추천 결정을 대체한다.
   - 기각: N×M 시뮬레이션과 재고를 대시보드에 넘기면 배정 결과를 파이프라인에서 검증할 수 없고 계산 책임이 중복된다.
