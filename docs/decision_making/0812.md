# 8월 12일 의사 결정 목록

---
1. Airflow 인프라(EC2 v.s. ECS Fargate)
    > Airflow를 EC2+Compose로 운영할까 ECS에서 운영할까
    - 결론 : EC2 사용
    - 사유 : 
        1. 사용하는 DAG 수가 너무 적음,
        2. 장애 대응 요구 시간이 넉넉함
        3. 수집 주기가 대체적으로 길다.
2. Iceberg 도입 여부
    > Iceberg를 쓰는게 오버엔지니어링이 아닌가?
    - 결론 : 도입 찬성
    - 사유 : Iceberg가 꼭 필요하진 않다. 다만, 확장성을 고려하고 재시도나 백필 가능성 등을 고려할 때 정당하다고 판단했다.
        - 도입해야 하는 이유
            - Schema 변경될 가능성이 있다. (2025년부터 congestion이 추가되는 등 앞으로도 변경될 가능성 농후)
            - 파티션 방식이 바뀔 수 있다.
            - 과거 버전 추적이 필요하다.
                - 과거에 계산을 어떻게 했는지 (계산 로직 변경에 대응)
                - 과거에 결과가 어땠는지 등 
        - 도입하지 않을라 했던 이유
            - 과거 데이터 UPDATE/DELETE가 거의 없다.
            - 데이터 재처리가 거의 없을 것이다.
3. Hive Style Partitioning 도입
    > 아무데나 Hive Style 적용하면 성능 문제가 생길 것 같은데 괜찮나
    - 결론 : S3 기준 모든 데이터에 도입 / Iceberg 파티셔닝은 HVFHV에만
    - 사유 :
        - 1KB도 안 되는 일 단위 수집 데이터에 파티셔닝 도입하는 것은 오히려 손해
        - 하지만, S3에서는 Hive Style Partitioning을 도입함으로써 결과를 스냅샷 형태로 잘 저장하고 관리할 수 있다. (과거에 어떻게 실패했는지 등 확인 가능)
