# 8월 21일 의사 결정 목록

1. 원천 API 3종 Silver 버전 보존 방식
   - 결정: `year_month/<collected_at>.parquet` 파일을 버전으로 누적한다.
   - 같은 `collected_at` 재시도만 동일 파일을 교체하고 과거 버전은 보존한다.
   - Gold는 각 데이터셋의 최신 최종 버전만 선택한다.

2. 검증 완료 상태 표현
   - 결정: 별도 `_SUCCESS`·`.pending` 상태를 만들지 않는다.
   - Spark/Lambda writer가 내부 임시 경로에서 최종 파일로 원자적 교체한다.
   - Airflow는 최종 파일을 읽어 검증하고, 실패 시 감시 DAG가 ETag 상태를 기록하지 않는다.
   - 기각: 별도 완료 표식과 2단계 확정은 현재 복구 요구보다 복잡하다.

3. HVFHV 버전의 물리 파일 수
   - 결정: 월 2,040만 행을 `coalesce(1)`로 단일 Parquet에 쓴다.
   - 장점: 버전 파일 선택과 보존 규칙이 단순하다.
   - 위험: 전체 셔플은 없지만 마지막 쓰기가 한 executor에 집중된다.
