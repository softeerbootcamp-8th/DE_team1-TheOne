# 8월 10일 의사 결정 목록

1. 차 등급 구분
    > 크롤링이 가능한 것은 Premium급인데 어떻게 처리하는 것이 좋을까?
    - 결론 : Premium만 추출하고 나머지는 Standard로 적용
    - 사유 : 택시 리스 업체이기 때문에, 택시 운행이 가능한 차만 보유할 것이다. 따라서 무조건 Standard 또는 X는 만족할 것이다. 따라서, Premium/Comport에 해당하는 차만 조사하여 등급 부여

2. 문제 재정의
    > 예상 이탈률은 우리가 구할 수 없다. 만들게 되면 가짜 프로덕트가 된다. 그럼 무슨 문제를 풀어야 할까?
    - 결론 : 기사에게 더 높은 순수익을 주면서도 리스 업체의 객단가를 끌어올릴 수 있는 차량을 데이터 기반으로 추천하지 못해 `객단가 향상 기회 상실`
    - 사유 :
        - 회사 입장에서 고객 1명 당 최대 수익을 얻는 것이 매출 향상으로 이어진다. 다만 이때, 아무한테나 추천해서는 교체로 이어지지 않는다. 비싼 차량으로 바꿨을 때 높은 순수익을 줄 수 있는 사람에게 추천해줘야 교체 가능성이 높기 때문에 문제를 순수익 + 객단가로 조합해서 설정했다.

3. Airflow 호스팅 위치
    > Airflow Local V.S. EC2
    - 결론 : EC2에 올리기로 결정
    - 사유 : 현대차 현직분들 멘토링을 통해 여쭤보았을 때 Airflow를 Local에서 돌리는 것은 말도 안 되는 선택이라고 하셨다. Local은 어떤 일이 일어날지도 모르고, 스케일링도 어려운 등 여러 문제가 있기 떄문이다. 따라서 조언에 따라 비용이 증가하더라도 Airflow를 EC2에 올리려고 한다.

4. Airflow task 단위
    - 결론 : 기본적으로 논리적 단위로 묶은 것을 Task로 정의, 5분 이상 걸리는 작업은 Task 분리
    - 사유 : Airflow의 Task를 잘게 쪼갤수록 문제가 생겼을 때 실패 지점부터 돌릴 수 있다는 장점이 있다 다만, 잘게 쪼갤 수록 Schedule할 것이 늘어나기에 Memory 문제가 발생한다. 즉, Trade-off로 메모리<->실패 복구 시간을 갖는다. 
        - 우리는 메모리가 넉넉하지 않다는 문제도 있기 때문에 논리적 단위로 묶은 후, 5분 이상인 작업만 분리하기로 했다.
