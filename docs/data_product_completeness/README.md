# 데이터 프로덕트의 완성도

뉴욕에서 Uber·Lyft 기사에게 차량을 리스하는 업체의 담당자가, **차를 바꾸면 기사와 회사가 함께 이득인 고객**을 골라 전화할 수 있게 만든 대시보드입니다. 그 제품이 얼마나 갖춰졌는지를 세 문서로 나눠 정리했습니다.

| 문서 | 답하는 질문 |
| --- | --- |
| [01 무엇을 만들었나](./01_product_overview.md) | 누구의 어떤 문제를, 어떤 기능으로 풀었나. 무엇을 넣으면 무엇이 나오나 |
| [02 어떻게 도는가](./02_e2e_pipeline.md) | 원천에서 대시보드까지 어떤 단계를 지나고, 잘못된 데이터를 어디서 막나. 어떻게 실행하고 복구하나 |
| [03 무엇이 됐고 무엇이 안 됐나](./03_implementation_status.md) | 된 것, 안 되는 것, 다음에 할 것 |

## 평가 기준별로 어디를 보면 되나

| 기준 | 문서 |
| --- | --- |
| 수집·처리·저장·분석·제공 전 과정이 문제없이 도는가 | [02](./02_e2e_pipeline.md) — 다섯 단계, 검증 지점, 두 번 돌려도 같은 결과가 나오게 하는 장치, 실행·복구 절차, 운영 중 실제로 겪은 5건 |
| 기획한 기능이 실제로 구현됐는가 | [01](./01_product_overview.md) — 기획 요구와 구현을 나란히 둔 표, 추천 알고리즘이 v1 에서 v2 로 바뀐 이유, 계산 방법 / [03](./03_implementation_status.md) — 된 것 목록 |
| 결과물을 담당자가 이해하고 쓸 수 있는가 | [01](./01_product_overview.md) — 담당자가 쓰는 순서와 화면 요소별로 얻는 것 / [03](./03_implementation_status.md) — 결과 한 행에 무엇이 담기나 |

## 문서에 적힌 숫자의 출처

| 종류 | 어디서 확인했나 |
| --- | --- |
| 데이터 구조와 컬럼 | `schema/` 의 정의 파일 |
| 실행 시각과 트리거 조건 | `main/airflow/dags/` |
| 임계값·허용 오차·계산 상수 | 해당 소스의 상수 정의 (주석에 실측 근거가 있음) |
| 화면 구성과 필터 동작 | `main/dashboard/app.py` |
| 테스트 수 | `make test` 실행 결과 |

전체 아키텍처 그림은 [프로젝트 README](../../README.md#데이터-파이프라인), 서버·네트워크 구성은 [AWS 인프라](../AWS_INFRA.md), 관측 구성은 [모니터링 구축](../MONITORING.md)에 있습니다.
