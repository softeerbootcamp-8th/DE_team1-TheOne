# 차량 추천 결과 검증

- 요약
  - 문제 : 파일/스키마 정상 여부와 관계없이 대시보드에 틀린 결과가 제공될 수 있음
  - 접근 : 저장 전에 아래 검사
    - 기사 누락 방지
    - 기사별 한 행
    - 재고 일치 확인
    - 연료비 존재 확인
    - 기대 수익 양수 확인
  - 검증 : 작업은 성공하지만 결과가 틀릴 수 있는 상황을 시나리오로 작성 후, 자동화 테스트 진행

## 문제
- 배경
  - 대시보드에 표현되는 값 : **기사별 한 달 운행 실적**, **추천 차량**
    - 이 두 개는 컬럼/타입이 맞아도, 사용할 수 없는 값일 수 있음
      - ex, 일부 기사 결과 누락 / 기사별 결과 2행 생성 / 재고 개수 안 맞음 등
- 문제 : 위와 같은 문제가 **실패**로 나오지 않음
  - 실제 대시보드를 확인해야 문제를 알 수 있다. (심지어 확인해도 모를 수도 있다.)

## 접근
- `데이터 형식(스키마) 검사`랑 `제품 규칙 검사` 분리
  - 형식 검사: 필수 컬럼, 타입, 빈 데이터 여부 확인
  - 계산 가능성 검사: 운행 날짜에 대응하는 연료비가 모두 있는지 확인
  - 제품 규칙 검사: 기사 보존, 결과 유일성(기사 별 1행), 재고 일치, 기대 수익 확인
    - 제품 규칙 검사를 가장 마지막에 실행

## 해결
> 추천 계산 직후 다음 순서로 검사
1. **결과 유일성** : 아래 항목이 정확히 `기사당 1행`인지
  - 기사별 한 달 운행 실적
  - 추천 차량 결과
2. **기사 수 일치** : `추천 결과`와 `운행 실적`의 기사 수가 같은지
3. **계산 가능성 검사** : 예상 순수익 계산을 위한 아래 정보가 있는지
  - 운행 날짜별 연료 요금
4. **차량 재고 일치** : 아래 식을 위반하지 않는지
  - 차량 모델별 추천 수 <= 현재 미운행 중인 차의 수
5. **비즈니스 로직 일치** : 아래 식을 위반하지 않는지 
  - 추천 차량으로 변경시 `예상 순수익 증가량 > 0`

## 검증
> 잘못된 추천 데이터를 넣는 것을 방지하기 위한 테스트 생성 후 검증
- 아래 시나리오별 테스트를 만들어 확인
  - **추천 후보 제외 확인** 
    - 재고 0인 차량 추천 후보에서 제외
    - 수익 0이하인 차량 추천 후보에서 제외
  - **재고 불일치 실패 확인** : '운행 차량 + 추천 차량 > 전체 재고'면 실패
  - **계산 불가 실패 확인** : 대상 월의 연료비 없을시 계산 중단
  - **기사 누락 실패 확인** : 추천 결과에 기사 누락시 DB 연결 전에 실패
  - **유일성 확인** : 최종 추천 기사당 한 행
