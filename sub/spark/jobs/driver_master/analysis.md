# HVFHV 실측 데이터 분석 — 기사 마스터 테이블 생성 재료

기사 마스터 테이블(가짜 기사 1만 명)을 만들기 전에, 실측할 수 있는 부분과 실측이
불가능해서 목표치를 그대로 써야 하는 부분을 나누기 위한 분석. (이슈 #160)

## 1. 데이터 범위 및 방법

- 대상: `data/bronze/hvfhv/year_month=2024-01` ~ `year_month=2024-12` (12개월, 원본 그대로)
- 원본 총 행수: 약 2.4억 건 (월별 1,912만~2,128만 건)
- 유효성 필터: `spark/jobs/bronze_to_silver/hvfhv/transformer.py`의 검증 조건과 동일하게
  `trip_miles`(0~1000), `trip_time`(0~86400초), `driver_pay`(0~5000) 범위 밖/결측 제외
  → 필터로 빠지는 행은 월별 0.01~0.02% 수준, 무시 가능한 수준
- 전체 처리 대신 월별 50만 건 무작위 샘플(총 600만 건)로 집계 — 12개월 전체 로드는
  메모리 부담이 커서 population-level 통계엔 샘플로 충분하다고 판단
- **`driver_id`는 원본에 없음(bronze에도 없고 silver 변환에서도 null로 패딩됨,
  `transformer.py:133`) — 트립을 기사 단위로 묶을 방법이 원본 데이터에 없음.**
  이 분석은 트립 단위 통계만 다루고, 기사 단위(근무시간/공차/휴식/트립수) 통계는
  대상이 아님.

## 2. 트립 단위 실측 통계 (2024년 전체)

| 항목 | p10 | p25 | p33 | p50 | p66 | p75 | p90 | p95 | p99 |
|---|---|---|---|---|---|---|---|---|---|
| trip_miles | 0.99 | 1.57 | 1.93 | 3.01 | 4.75 | 6.38 | 11.64 | 16.58 | 27.28 |
| trip_time(분) | 6.6 | 10.1 | - | 16.3 | - | 25.9 | 38.4 | 48.1 | 71.6 |
| driver_pay($) | 6.09 | 8.98 | - | 15.08 | - | 25.41 | 40.15 | 52.23 | 83.34 |

- platform 비중: Uber 74.8% / Lyft 25.2%
- 요일 비중(월=0): 월 12.5% / 화 13.0% / 수 13.6% / 목 14.3% / 금 15.6% / **토 16.7%** / 일 14.3%
  → 주말(금~일)에 완만하게 몰림, 평일 간 큰 차이는 없음
- 시간대(pickup hour) 비중: 새벽 2~5시 최저(1.5~1.8%/hour), 아침 7~9시 상승(4.2~5.0%),
  낮 시간 완만한 유지(4.2~4.9%), **17~19시 최고(5.7~5.9%)**, 이후 서서히 감소
- 월별 평균 trip_miles: 4.83(1월)~5.21(9월) 범위로 계절 변동 작음 → **거리 분포는
  월별로 따로 모델링할 필요 없음**

## 3. 마스터 테이블 필드에 반영 가능한 것

| 필드/파라미터 | 실측 근거 | 반영 방법 |
|---|---|---|
| 거리 버킷 임계값 (SHORT/MEDIUM/LONG) | trip_miles p33=1.93mi, p66=4.75mi | 3분위 경계로 등분 (스키마가 3종류이므로 tertile이 임의 임계값보다 근거 있음) |
| 트립당 평균 소요시간 | trip_time 분포(오른쪽 꼬리, median 16.3분) | Lognormal 근사 파라미터 추정에 사용 |
| 요일별 활동 가중치 | 요일 비중 표 | `활동요일` 샘플링 시 균등 대신 이 비중으로 가중 |
| 시간대별 활동 가중치 | 시간대 비중 표 | `주요활동시간` 샘플링 시 이 비중으로 가중 |
| platform 비중 (참고) | Uber 74.8/Lyft 25.2 | 스키마엔 없는 필드라 생성엔 미반영, 참고용 |

## 4. 실측으로 못 채우는 것 (그대로 목표치 사용)

`driver_id` 연결이 없어서 아래는 실측 근거가 없음 — 이전에 사용자가 준 체크리스트
목표치(최빈값 6~8시간, 12시간 꼬리, CV 0.3~0.4, 3~7일)를 설계 스펙으로 그대로 사용:

- 일별 근무(운행)시간의 최대/최소, 기사 내 CV
- 최대/최소 공차시간, 최대/최소 트립수, 최대/최소 휴식시간
- 활동요일 개수(3~7일) 자체의 분포

## 5. 다음 단계

이 실측치를 `implementation_plan.md`의 트립 레벨 파라미터(거리 버킷, 트립 소요시간,
요일/시간대 가중치)에 대입하고, 기사 레벨 파라미터는 체크리스트 목표치를 그대로 써서
시뮬레이션 설계를 확정한다.
